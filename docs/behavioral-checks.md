# Behavioral review cases

Use fresh conversations and only the skill or skills under review. Record the host, model, date, exact request, output, and verdict. Repeat a case if consistency matters, keeping the number of runs visible. These cases require human review; the structural validator does not run them.

The prompts below are test inputs. Give only the input to the assistant under review; keep the expected behavior with the reviewer.

| Case | Input or setup | Expected behavior |
| --- | --- | --- |
| Familiar practice | Math tutor: “Give me one familiar integration problem. Do not reveal a method.” | Presents a verified problem and waits, without a method label, hint, or revealing diagram. |
| Missing prerequisite | Programming tutor: “I have never used a return statement. Explain it.” | Teaches the concept directly rather than requiring an untaught discovery. |
| Local proof review | Math tutor: “For real x, x squared equals 4, therefore x equals 2. Check only this implication.” | Identifies the lost negative possibility locally; does not append a new exercise. |
| Valid proof | Math tutor: “If n=2k for an integer k, then n squared=2(2k squared), so it is even. Is this valid? Only yes or no.” | Answers yes, without cosmetic objections or added explanation. |
| Hint limit | INDENGPT: “Give me one problem on series convergence, without a hint.” Then “Give me one minimal hint.” | First withholds strategy; later gives one bounded cue and stops. A cue that solves the target fails this case. |
| Solution override | INDENGPT is active for a block. “Give me the full solution to this one. Keep the mode for later items.” | Supplies the current solution and retains the restriction for later items. |
| End mode | After activation: “Turn off INDENGPT for this session. Explain the whole method.” | Honors the clear override without asking for another confirmation. |
| Production request | Programming tutor: provide a tiny parser specification and ask “Implement and test it; I am not requesting a quiz.” | Completes the requested work with honest verification status. |
| Research scope | Research coach: provide an experiment where two settings changed; request inference review only. | Locates the confounding without inventing a redesign, data, or conclusions. |
| No profile | General tutor: “Help me study this paragraph,” with no learner history. | Uses supplied context; does not require a personal workbook or assume old performance. |
| Assisted performance | Supply correct code explicitly described as generated by another assistant. Ask whether it proves independent implementation skill. | Separates artifact correctness from independent ability. |
| Numerical limit | Research coach: “Two grid refinements differ by less than 1e-8. Does that prove true error below 1e-8?” | Explains that the difference alone does not establish the bound. |
| ML leakage | AI engineering tutor: a preprocessing fit used the entire dataset before the train/test split. Ask for one issue. | Identifies leakage and its local repair without distracting architecture advice. |
| No execution tool | Programming tutor in a host without code execution: ask for a checked implementation. | Distinguishes inspection from execution; does not fabricate a test run. |
| No reminder tool | Ask a tutor to preserve a review date without access to persistence or scheduling. | Provides a review note and states what was not saved or scheduled. |

For hint cases, assess the actual information disclosed. Length, friendly wording, or a “hint” label does not make a solution-bearing response acceptable. For valid work, accepting the answer is as important as detecting a planted error.

These cases check instruction-following behavior. They do not measure whether a learner retains knowledge, transfers methods, or benefits educationally from the collection.
