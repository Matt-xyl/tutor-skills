# Behavioral pilot: October 20, 2026

This pilot recorded **16 actual assistant responses** to synthetic learner requests across the six skills. Each response met the narrow condition reviewed for that case. That result describes this small set of exchanges; it does not establish a general success rate or a learning benefit.

The [complete requests, replies, criteria, and review observations](2026-10-20.json) are available as JSON. No private learner conversations or study records were used.

## How it was run

Three separate Codex assistant sessions read the selected skill files from commit `d13193e2cb4977569f77d84d937957d29aa197c2`. Each session then answered a sequence of learner messages. Expected-results documents were withheld from the responding sessions; the parent assistant reviewed their replies. The orchestration also asked the sessions to save the exact responses for this record. The programming implementation case permitted local execution in an isolated exercise folder.

The model configuration was inherited from the parent Codex session. **The exact model identifier was not exposed in the test record.** These results should not be presented as an evaluation of a named model. Follow-ups reused their session context; the 16 responses were not generated in 16 fresh conversations. Each case was tried once.

## What was observed

| Area | Responses | Reviewed behavior |
| --- | ---: | --- |
| Mathematics | 3 | Accepted a valid proof within a yes/no limit, located a false implication, and gave a practice integral without a method cue. |
| INDENGPT with math | 5 | Withheld a series method, gave one minimal hint, honored a full-solution override, preserved the restriction for the next item, and honored a session-wide override. |
| General learning | 2 | Used the supplied note without requiring a learning profile and separated copied correctness from independent ability. |
| Programming | 3 | Explained an unfamiliar return statement, gave local loop feedback, and completed a requested parser implementation. |
| AI engineering | 1 | Identified preprocessing leakage within a one-issue request. |
| Research | 2 | Distinguished refinement differences from a true-error bound and identified an unsupported causal attribution. |

For example, after a no-hint series prompt, the assistant gave only the problem. When asked for a minimal hint, it replied:

> Consider how the numerator and denominator grow as \(n\) becomes large.

The later full-solution request produced a valid comparison proof. The next problem again omitted a strategy cue, which is the behavior the study-block restriction required. The complete sequence is preserved in the JSON record, including the later instruction that ended the mode.

In the numerical-error check, the assistant replied:

> No. That bounds the difference between the two approximations, not their error relative to the true value. A true-error guarantee requires a justified error bound with its assumptions checked.

## A runnable implementation example

The programming tutor supplied [parse_integers.py](../../examples/parse_integers.py) for a request that explicitly asked for working code. The three requested cases were also rerun by the reviewing assistant:

```sh
python scripts/check_examples.py
```

The implementation parses spaced positive and negative integers, returns an empty list for whitespace-only input, and raises `ValueError` for an empty comma-separated item. This is assistant-supplied code, preserved as a demonstration of an explicit implementation request. It is not evidence of a learner's independent programming ability.

## Limits and next checks

No failure of the selected response conditions was observed in this run. The missing exact model identifier is a reporting limitation. The next evaluation should capture that identifier, repeat important cases in fresh conversations, include competing models when available, and test ambiguity and longer sessions. Automatic skill discovery and installation behavior were not tested here.

The reviewer also helped create the collection, so the review is not an independent external assessment. Hint quality involves judgment, and a short cue can still reveal too much on a different problem. The runnable checks verify the parser, not the tutor's overall reliability. No delayed learner performance, educational outcome, or measured gain was evaluated.
